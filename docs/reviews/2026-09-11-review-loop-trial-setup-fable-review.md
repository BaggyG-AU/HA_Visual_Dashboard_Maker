## 3. Findings in detail

**P1 — SEV 2 — the authority exists only locally.** `b08bc41` and `eee6928` are on `feature/codex-review-loop-analysis`, which has no counterpart on `origin` (the worktree at `/home/micah/projects/HA_Visual_Dashboard_Maker-codex-review-loop` is its only checkout). The assessment card, the pause watch's exception paragraph and `drawer_havdm_decisions_e2f130d23c11e6dacf94f42d` cite that commit. Under §3 class (b) a substantive governance change lands as a committed, independently reviewed document the owner merges; this review can serve as that review for the setup, and the package itself carries both agents' agreement across exchanges 1–4. The fix is one push and one docs-only PR; the agent opens PRs.

**P2 — SEV 3 — the history's home.** The charter (`drawer_practice_charter_f9efb6904018fb7a2021bd64`) splits reusable rules from project case studies, but this narrative is neither: it is the wing's own changelog, and one paragraph of it is the cross-project founding record. The index already sets the precedent for a non-rule drawer in `practice` / `charter`. A wing-filtered search from promptmi or nudge-book would not see a HAVDM investigation. Retrieval by ID works from any wing, so this does not block application.

**P3 — SEV 4.** In the proposed middle section the pointer reads `- {{HISTORY_DRAWER_ID}} — Historical provenance…`; every other pointer in the index is backticked. The history header should also name the source hash so the relocation is auditable without the bundle.

**P4 — SEV 4.** "Codex prepared this record; Fable's check of the added contract wording is pending." appears in #159, F6, F10 and by reference in the adoption record. It becomes stale on the owner's acceptance.

**P5 — SEV 4.** The backlog's S02.1 row limits the menu to "only what makes sense with no card under the cursor". The F6 card's description says "not a request for extra menu features", but criterion 2 says only "an appropriate context menu offering Paste".
