## 3. What the Fable review missed

### N1 — high: the dedicated correction left two of five audited plan claims false

Fable repeated the same grouping error it criticised. Audit F2 contains two false plan claims, not one: dropping Control 11 and claiming every evidence error had been corrected while Control 12 remained incomplete. The complete plan-claim population is five; `50210c6` corrected three and left these two adjacent claims on `main`:

The file's own `:138-142` admission that Control 12 is still under-specified directly contradicts the first. Both need correction, not only Fable's proposed one-line no-CI edit.

### N2 — high: run `32091030021` does not demonstrate a docs-only selector defect

The final commit `f9bc049` was Markdown-only; the pull request diff that `--only-changed=origin/main` evaluated was not. `git diff --name-status ae4cbdf..f9bc049` contains 20 test/support files, including `tests/support/dsl/canvas.ts`, `tests/support/dsl/entityBrowser.ts`, 17 e2e specs, and one integration spec. The shared DSLs flow through `tests/support/index.ts` into a broad test population.

The run log mechanically confirms the result: tier 1 listed 314 e2e tests in 70 files and 217 integration tests in 21 files; e2e completed 311 passed / 1 failed / 1 flaky / 1 skipped before integration ran into the job limit. That is a broad and expensive selection, but it is selection against the whole test-changing PR, not a docs-only diff. Fable's “verified broken” diagnosis at `docs/reviews/pr144-independent-performance-governance-review.md:536-547` and the same assertion in its MemPalace diary are false.

The useful follow-up question is narrower: whether changing `canvas.ts` really justifies 531 behavioural tests, and how to make a **PR-wide** docs-only change skip behavioural work without skipping test-bearing history. Path filters must not classify a mixed PR from only its latest commit.

### N3 — high: Option A is not a trial of the proposed role split

The proposed table assigns Sonnet to implementation review. Fable's trial assigns Claude to implementation review (`docs/reviews/pr144-independent-performance-governance-review.md:316-323`) and then says the result can decide the full split. That trial can measure Codex implementation and Claude review; it cannot measure Sonnet review. It also preserves the audited agent in the central checking seat, so the conflict-of-interest concern is real rather than merely apparent.

If the owner wants to test the promptmi table, Sonnet must occupy the reviewer seat and the trial must specify what independent evidence judges that review. If the owner prefers Claude because its HAVDM checking record is stronger, call that a different role design and do not present it as evidence for Sonnet.

**Interest declared:** I am the proposed implementer, authored the seven PR #144 review rounds, and have an interest in retaining review work. I therefore separate two claims. Codex has not owned and delivered an end-to-end HAVDM implementation slice, so that role remains unmeasured in the strict project-delivery sense; the headless probes, extracted harnesses, mutants, and worktree experiments are nevertheless real implementation-capability evidence, so “zero signal” would be false.
